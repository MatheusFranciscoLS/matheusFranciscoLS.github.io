CogniVault

A parts catalog and counter quoting system for a machinery and parts dealer. The clerk types a code, a part name or a machine model and leaves with the price, the position in the diagram and a ready quote, without the system ever guessing a code.

The problem

At a dealer's counter the customer is standing in front of the clerk. Answering "which part is it and how much?" meant opening a PDF catalog, finding the position in the diagram, checking the price in a list, seeing whether the part was on the shelf and building the quote by hand. Each step came from a different source, and a wrong code becomes a return.

The solution

A single system designed for a computer with mouse and keyboard and for people serving customers in a hurry: search by code, part name, model or PNC; the official exploded view with a clickable position; the list price, an old-price warning and the shelf from the ERP; and a PDF or WhatsApp quote that wraps up the request with no extra steps.

Rules the product never breaks

Never guess a code

A typed code returns only the exact code and the manufacturer's official replacement. Nothing "similar". The AI only picks from a closed list of parts for the machine, and the server discards any answer outside that list.

Customers never see the part code

PDFs, WhatsApp messages and printouts leave without the part code, so the customer cannot price it at another dealer with our number.

The clerk wants the part, not an explanation

No text about how the system works. Every empty state has a way forward: a button, an official link or a field to type in.

Keyboard first

Ctrl+K focuses the search, arrows walk the results, Enter copies the code, + adds the part to the quote.

Data changes are explicit

Importing prices or shelves shows a report before writing and keeps an undo. Nothing is created or deleted behind the scenes.

Zero cost

Vercel, Render, Supabase, CloudAMQP and GitHub Actions on free tiers, with no paid dependency.

Architecture

The store's ERP runs on a local network the cloud cannot reach. So the integration is export, review the report, import (with undo), never a live read.

Decisions and what I learned

The green test that lied

A job that deletes quotes older than 1 year (for privacy) had a passing test. In production it never ran: the line that started it sat inside the RabbitMQ retry block. I found it by looking at the database two days later. Now there is a test just for the wiring, proven by undoing the fix and watching the test fail.

The cart that never loses a quote

The production log showed a Prisma transaction blowing past the default 5 seconds (6.7 s) on a cold free-tier database, and the clerk's quote stayed only in the browser. The cart is now saved whole and idempotently, with a longer timeout and automatic retries with growing waits. Two tabs of the same browser become a single cart.

"Today" ended yesterday

The server runs in UTC and the store in UTC-3: the "until today" filter cut off at 11 pm yesterday and the owner could not see the day's own quotes. Every day calculation now uses the store's time zone, locked by a test.

Refusing beats being wrong

The PDF catalog reader prefers to refuse a doubtful file, saying why in the admin panel, rather than save a wrong code that would poison the whole search. And after an audit, a typed code now returns only the exact match: an "almost equal" code at the counter is a return.

Testing the way the clerk types

End-to-end browser tests against a simulated store exercise what people really type: lowercase, a space instead of a dash, pasted codes, emoji, nonsense, 1,500 characters. Each important fix is proven by mutation: undo the fix and check that the test fails.
